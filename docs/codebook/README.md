# 코드북 만드는 법 (#28)

코드북은 사람과 AI가 말한 쓰는 이유·안 쓰는 이유에 붙이는 이름표 목록이다. 사람 답과 AI 답에 같은 이름표를 붙여야 둘이 같은 이유를 말했는지 셀 수 있다. 정리 담당은 사람 답에, 판정자는 AI 답에 이 코드를 붙인다.

`코드북_양식.csv`를 복사해서 채운다. 엑셀로 열린다.

## 칸

| 칸 | 내용 |
|---|---|
| code | 안 쓰는 이유 공통은 C01부터, 기능은 F1-01처럼 기능 번호로 시작. 쓰는 이유는 U01, F1-U01 |
| scope | 공통, 기능, 기타, 제외 중 하나. 기타(C98, U98)는 서로 맞았다고 세지 않고, 제외(C07, U05)는 기능 판정에서 빼서 따로 센다 (`코딩규칙.md` R2) |
| kind | 안 쓰는 이유 또는 쓰는 이유 |
| name | 짧은 이름. 기말 데모 화면(#35)에 그대로 뜬다 |
| 정의 | 이 코드를 붙이는 경우를 한 줄로 |
| 예시 | 이 코드에 해당하는 문장 한 줄. 리포가 공개라 응답 원문 그대로 쓰지 않고 고쳐 쓴 문장으로 |
| 출처 | 폼 보기에서 왔는지, 어디서 나온 이유인지 메모 |

판정 계산기는 code, scope, name만 읽는다. 나머지 칸은 사람이 보려고 둔다.

코드를 붙이는 순서와 규칙은 `코딩규칙.md`에 있다. 이유가 없는 답("그냥")은 코드 대신 `-`를 쓴다.

## 공통 코드와 기능 코드 나누는 법

- 어느 기능에 갖다 붙여도 뜻이 그대로면 공통 코드다. "필요 없어서", "다른 방법으로 해결해서"
- 그 기능에만 있는 것을 말하면 기능 코드다. 마감 알림의 "알림이 너무 자주 와서 껐다", 추천 공고 목록의 "추천이 내 분야랑 안 맞았다"
- 뜻이 같으면 기능이 달라도 같은 공통 코드를 쓴다. 기능마다 따로 만들면 "아무 기능에나 할 말" 기준점이 망가진다 (`docs/measurement/판정계산기.md` 4장)

## 순서

1. 공통 코드는 양식에 폼 4-5·4-6 보기로 미리 넣어 두었다. 이름이 맞는지 보고 정의와 예시를 채운다. 4-5 "써보니 불편해서"와 4-6 "쓰기 번거로워 보여서"를 C03 하나로 묶었는데, 나눌지는 작성자가 정한다
2. 기능 4개마다 그 기능에서만 나올 것 같은 이유를 예상해서 기능 코드 줄을 늘린다. 응답을 보지 않고 예상할 때 참고할 것: 서비스 앱·웹 화면, 앱 마켓 리뷰(우리 응답자가 아니라 봐도 된다), 자기 경험
3. 쓰는 이유(4-4)도 같은 방식으로 만든다
4. 파일럿 응답을 받으면 보고 빠진 이유를 더한다. 파일럿으로 쓴 응답은 본 판정에서 뺀다
5. 정리 담당이 파일럿 답에 직접 코드를 붙여 보고, 헷갈리는 코드는 정의를 고치거나 합친다
6. 확정하면 `docs/codebook/코드북.csv`로 커밋해서 고정한다. 본 응답 정리를 시작하기 전에 끝낸다

## 지킬 것

- 코드 하나에 뜻 하나
- 너무 잘게 쪼개지 않는다. 한 기능에 코드가 대여섯 개를 넘으면 합칠 수 있는지 본다
- 응답 원문을 본 사람(폼 소유자)은 코드북을 쓰지 않는다 (폼 문서 246행)
