# SimTrust 코딩 규칙 v0.1 (2026-11-08)

담당: 김승하 (#28). 코드는 `코드북_초안.csv`, 코드북 칸 설명은 `README.md`에 있다.

## 0. 코딩 순서
1. 서술을 이유 단위로 쪼갠다 (단위 하나에 코드 하나)
2. 기능을 정한다: 응답자가 앞에 붙인 기능 이름을 따른다 (R7)
3. 쓰는 이유인지 안 쓰는 이유인지 정한다
4. 그 기능의 F 순서도 → 해당 없으면 공통 순서도
5. 대체 수단, 세부 유형, 메모 칸을 채운다
6. 조건·페르소나는 가린 채로 코딩한다 (블라인드, 6장)

## 1. 기능 범위
- F1 검색·필터: 필터 바 + 검색창 + 정렬. 상단 메뉴 이동과 스크롤은 둘러보기(F1 아님)
- F2 저장: 저장 버튼(스크랩, 찜, 북마크) + 저장 목록
- F3 마감 알림: 스크랩한 공고의 마감 알림 + 알림 설정 화면
- F4 추천: 서비스가 골라 보여 주는 목록 전체 (맞춤, 인기, 광고 추천) ※ P09 결정 대기

## 2. 규칙
- R1 구체적인 코드가 우선이다 (F > 공통, 원인 > 결과). 단, F 코드는 정의와 맞을 때만 붙인다. 문장에 기능 이름이 나왔다는 것만으로는 F 코드가 아니다
- R2 기능과 상관없는 이유(C07, U05)는 기능 판정에서 빼고 따로 센다. 코드북 scope를 `제외`로 두면 계산기가 그 사람은 칸 인원에 넣고 이유는 판정에서 빼서 `metrics`의 `codebook.excluded_codes`에 따로 센다
- R3 써봤는지 여부는 코드로 나누지 않고 사용 상태 칸(`kind_label`)으로 본다
- R4 이유 없이 "그냥"만 말하면 코드 대신 `-`를 쓴다 (판정 시트와 같은 규칙. 그 칸에 답한 사람 수에는 들어간다)
- R5 맞는 F 코드가 없으면 공통 코드로 보내고 메모에 "F 후보: 내용"이라고 적는다
- R6 같은 이유 안의 세부 정보는 칸으로 기록한다 (대체 수단, 세부 유형)
- R7 기능은 응답자가 붙인 기능 이름을 따르고, 코드는 내용을 보고 붙인다. 다른 기능의 F 코드는 붙이지 않고 공통 코드를 쓴 뒤 메모에 "F3 연동"처럼 적는다

## 3. 순서도 (위에서부터, 처음 맞는 곳에 넣는다)

### 안 쓰는 이유 — 기능별
- F1: 원하는 조건을 고를 수 없음 F1-01 → 조건은 걸었는데 결과가 이상함 F1-02
- F2: 쌓이거나 섞여서 관리가 어려움 F2-02 → (쌓인 이유 없이) 다시 안 봄 F2-01
- F3: 스크랩과 묶임 F3-05 → 웹만 씀·앱 없음 F3-03 → 이 앱 알림이 많음(양 표현) F3-01 → 알림 자체가 싫음 F3-04 → 시점이 안 맞음 F3-02
- F4: 광고 같아서 안 믿음 F4-02 → 같거나 비슷한 것만 뜸 F4-03 → 관심과 안 맞음 F4-01

### 안 쓰는 이유 — 공통 (기능별에 해당 없을 때)
C05 몰랐음·못 찾음 → C02 대체 수단 있음 → C06 로그인·정보 입력 → C07 요즘 쓸 일 없음 → C03 번거로움·어려움 → C01 필요 없다는 판단 → C04 판단 없이 안 해봄 → C98 기타 → `-` 이유 없음

### 쓰는 이유 — 기능별
- F1: 조건으로 거름 F1-U01 → 순서를 바꿔 봄 F1-U02
- F2: 지원하기로 정한 걸 관리 F2-U02 → 모아 두고 비교 F2-U01
- F3: 기능 전용 코드 없음 (공통으로)
- F4: 처음 알게 됨 F4-U01 → 관심에 맞게 알아서 뜸 F4-U03 → 남들이 많이 보는 걸 확인 F4-U02

### 쓰는 이유 — 공통 (기능별에 해당 없을 때)
U05 서비스 자체가 좋음 → U03 한곳에서 모아 봄 → U02 놓치지 않음 → U01 시간·수고가 줄어듦 → U04 습관 → U98 기타 → `-` 이유 없음

## 4. 칸 값
- 대체 수단 (`alt_means`): 같은 서비스 다른 기능 / 다른 공고 서비스 / 범용 앱 / 사람·학교
- 세부 유형 (`subtype`, F4만): 맞춤 / 인기 / 광고 / 구분 불가
- 값이 여럿이면 `;`로 나눈다. 없으면 비운다. 정해진 값이 아니거나 F4가 아닌 줄에 세부 유형을 적으면 가져오기가 멈춘다

## 5. 코딩 시트 (팀 스크립트 칸에 맞춘 것)
사람 답은 `scripts/form_to_sheet.py make`, AI 답은 `scripts/reason_sheet.py make`가 시트를 만든다. 둘 다 같은 규칙으로 채운다 (`docs/measurement/판정계산기.md` 1·2장).

| 코딩 시트 v0.1 칸 | 스크립트 시트 칸 |
|---|---|
| 응답ID | `row_id` (사람, 응답자 x 기능) / `item_id` (AI) |
| 서비스, 앱/웹 | `service`, `platform` |
| 기능(R7) | `feature_id`, `feature_name` |
| 사용 상태 | `kind_label` (계속 씀 / 안 써봄 / 그만둠) |
| 종류(쓰는/안 쓰는) | `kind` |
| 문장 번호, 쪼갠 문장, 코드 | 서술 원문은 `text_feature`·`text_all`(사람), `text`(AI). 쪼갠 이유마다 코드를 `;`로 이어 적는다. 한 칸에 코드 하나 |
| 코더 | 코더 1은 `code_1`, 코더 2는 `code_2`, 맞춰 본 뒤 `code_final` |
| 대체 수단, 세부 유형(F4) | `alt_means`, `subtype` |
| 메모 | `note` |
| 출처(사람/AI) | 사람 시트와 AI 시트를 따로 만든다. AI 시트에는 조건·페르소나·반복 번호가 없고 줄 순서가 섞여 있다 |

- 두 코더 kappa가 0.6에 못 미치면 가져오기가 멈춘다 (TRD NFR-07)
- 시트에는 응답 원문이 들어간다. `private/coding/`(커밋 제외)에 두고 저장소에 올리지 않는다

## 6. 코드 추가·변경
- 기타(98)나 "F 후보" 메모에 비슷한 내용이 2번 이상 나오면 새 코드 후보로 올린다
- 기타(98)는 코드북 scope를 `기타`로 둔다. 내용이 제각각이라 사람 기타와 AI 기타를 같은 이유로 맞았다고 세지 않는다
