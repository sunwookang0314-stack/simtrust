# SimTrust 사람 테스트 설계 v4 (검증 반영본, 2026-10-28)

v3 → 직접 검증(요구사항 대조·변경 시나리오 8개·드라이런) + 독립 검수 15건 반영. 10/7 데이터 수집 설계(비대면 폼)를 대체한다.

이 폴더에 있는 것
- `README.md`: 이 문서 (설계 본문)
- `data-flow.html`: 인터뷰 → 원자료 → 정답 계산 → 사람↔AI 비교 → 결과 흐름도. GitHub에선 소스로만 보이니 내려받아 브라우저로 열 것
- `data-flow.dataflow.json`: 흐름도 원본 스펙 (archify로 다시 그릴 때)
- `dryrun/dryrun.py`, `dryrun/dryrun_v4.py`: 가짜 세션으로 원자료 → 정답지 → 지표까지 계산해 본 검증 스크립트 (`python dryrun/dryrun.py`, 실제 참가자 데이터 아님)

## 원칙
1. 원자료는 판단 없이 넓게 남기고, 판단(그룹·결과 라벨·유형·이탈 정의)은 규칙 파일로 계산한다 → 기준이 바뀌어도 재인터뷰 없음
2. 규칙 파일은 AI 본실험 전에 해시로 동결한다. 다른 값으로 돌린 결과는 민감도 분석으로만 보고한다
3. 사람과 AI는 같은 문구, 같은 측정 방식(자기보고끼리)으로 비교한다
4. 분야가 바뀌면 갈아끼우는 건 3개뿐: 스냅샷 패키지(과제·화면·정답 경로), 대상자 조건, 유형 정의서

## 1. 모집 설문 (과제 보기 전, → participants.csv 비공개)
- 자격: 재학/취준, 학년, 출생연도, 졸업(예정) 연월, 4년제 여부, 성별, 학교, 전공 계열, 시·도
- 서비스별 사용 경험: 웹/앱 따로 (써본 적 없다 / 한두 번 둘러본 정도 / 여러 번 써봤다)
- '없다'가 아닌 사람 전원: 지금도 쓰는지(자주/가끔/거의 안 씀/그만둠), 마지막 사용 시점(구간값), 계속 쓰는 이유 또는 덜 쓰게 된 이유
  → 방금 겪은 불편에 오염되지 않은 실제 이탈 이유 (TRD 변경: FR-05-02는 과제 뒤에 물음)
- 선택 동의: 2~4주 뒤 "실제로 다시 써봤는지" 1회 연락 (동의자만 연락처를 그때까지 보관)

## 2. 배정
- 세션 시작 때 사용 경험 확정 → (링커리어 그룹, 캠퍼스픽 그룹) 조합 4가지 안에서 서비스 순서를 번갈아 배정 (ID 홀짝 배정 폐기)
- session_id는 무작위 토큰 (날짜·참가자 ID 안 들어감)

## 3. 세션 (약 40분, 진행자 + 기록자 2인 필수)
- 대면: 팀 노트북 / 화상: 진행자 PC 브라우저를 원격 제어로 넘김 (비밀번호 노출 없음, SEC-13). 창 크기는 캡처 해상도로 고정
- 동의: 녹음 + 브라우저 탭 화면 녹화(분석 동결 때까지 비공개 보관 후 삭제)
- 흐름: 시작 안내 → 소리 내 생각하기 연습 → [서비스 A: T1 → 직후 질문 → T2 → 직후 질문 → 시장성 → 괜찮았던 점 → 되묻기] → [서비스 B 동일] → 마무리
- 과제 수는 파일럿 뒤 확정 (서로 다른 이슈가 적게 나오면 T3 추가). 첫인상 질문은 폐기 (T1 직전에 메뉴를 훑게 만들어 "못 찾음"을 줄임)

## 4. 고정 문구 (AI에도 똑같이)
- T1 "관심 분야 공모전 하나를 찾아서 저장해 보세요." / T2 "마감 알림을 받도록 설정해 보세요." (알림 기능 확인 전)
- 직후 질문: 결과 자기보고(바로 했다/헤매다 했다/못 했다), 쉬움 1~7, 어디서 막히거나 헷갈렸는지
- 시장성 (전원, 그룹 분기 없음): 의향 1~5 → 쓰고 싶게 만든 점(Q_pos) → 안 쓰고 싶게 만든 점(Q_neg)
- 괜찮았던 점 (사람만): 써 본 화면 중 괜찮았던 부분 + 화면
- AI 제시 프로토콜 문서를 따로 만든다: 과제별 보여줄 화면과 순서, 서비스당 한 에피소드로 이어서 실행, T2 시작 상태 고정, 사람 시작 안내에 대응하는 AI 안내 문구. 진행 대본처럼 버전을 매긴다

## 5. 기록 (기록자)
- 과제마다: 스톱워치 시작·끝, 완료 여부, 방문 화면 순서(S번호 + 페이지 제목/URL, 스냅샷 밖은 S?+제목), 쉬움 점수, 결과 자기보고
- 관찰 결과 라벨은 계산: 미완료·시간≥상한 → 못 함 / 완료 + 정답 경로 목록 중 하나 + 기준 시간 이내 → 바로 함 / 그 외 → 헤매다 함. 시간 상한은 180초 이하로만
- 세션 직후 공용 임시 이슈 목록 갱신 (멈춤 기준 집계)

| sessions.csv | 비공개 | 토큰 session_id, mode, 진행자·기록자, script_version, protocol_version, 녹음·녹화 여부, 순서 |

| units.csv | 비공개 | 막힌 순간·이유·괜찮았던 점 하나 = 한 줄. 채널(소리 내 생각/직후 답/되묻기/관찰/자발/모집 설문), 화면(여러 값 허용), 녹음 시각, 기대·실제·행동, 요약, 원문 인용, 임시 유형(확정 유형보다 잘게), 다른 서비스 언급 여부, 정리자 A·B ID, 최종 ID |

| rules.json | 공개, 해시 동결 | 처음 그룹 값, 이탈로 칠 current_use 값, 정답 경로 목록·기준 시간·상한, 유형 매핑(사람·AI 공통), S? 처리, 노출 기준 k, 자료 부족 하한, 판정 문턱, 과제 없는 이슈·유형 충돌·자발 이유 처리 규칙 |

## 7. 매칭·지표 규칙
- 후보: 서비스 + 화면 집합이 하나라도 겹치면. 유형은 정렬 순서로만
- 셈: 재현율은 정답지 이슈의 유형으로, 정밀도는 가상 이슈의 유형으로. 유형이 다른 일치의 비율은 따로 보고
- AI 카드 유형은 제품에도 쓸 자동 추출기(FR-04)가 붙이고, 사람 쪽은 같은 유형 정의서로 코딩. 유형 매핑은 AI 카드를 보기 전에 확정
- 허위 근거: 처음 그룹 k명 이상이 지나간 화면에서 그 화면 정답지 이슈 0건, 또는 괜찮았던 점. 아무도 안 간 화면의 AI 지적은 "사람 노출 없음"으로 정밀도에서 빼고 건수만 보고 (TRD 변경: FR-06-02)
- 유형은 2단계(상위·하위)로 미리 정의. 하위 유형이 5건 미만이면 상위 유형으로 판정 (본실험 전 동결)
- 순서별 지표를 점검용으로 같이 냄
