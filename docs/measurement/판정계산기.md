# 판정 시트와 판정 계산기

- 작성: 김민우, 2026-11-05
- 측정 대상과 판정 기준 초안(`docs/measurement/측정대상-판정기준.md`, PR #36)을 코드로 옮긴 것이다
- 판정 규칙 값은 아직 팀이 정하지 않았다. `configs/rules.draft.json`은 스크립트를 시험하려고 둔 초안이고 `frozen: false`다
- 가짜 데이터로만 돌려 봤다. 사람 응답과 실제 AI 답으로는 아직 안 돌렸다

## 흐름

```
실행기 (run_simulation.py)        원시 응답
  -> 추출기 (extract_reasons.py)   기능별 쓸/안 쓸, 이유 줄
  -> 시트 만들기 (reason_sheet.py make)   판정자용 시트 + 대응표
  -> 판정자 2명이 코드북 코드를 채움
  -> 가져오기 (reason_sheet.py import)    AI 코드 CSV, 두 판정자 일치도
  -> 계산기 (score_reasons.py) + 사람 코드 CSV   칸별 통과율·재현율, 기준점, 판정
```

사람 응답은 이 흐름의 어느 스크립트에도 원문으로 들어가지 않는다. 정리 담당이 코드북으로 정리한 코드만 계산기에 넣는다. 폼에서 "외부 AI 서비스에 보내지 않는다"고 약속했고, 이 스크립트들은 외부 API를 부르지 않는다.

## 1. 판정 시트 (`scripts/reason_sheet.py`)

```
python scripts/reason_sheet.py make --extracted runs/dev/extracted/extracted_X.jsonl --out runs/dev/sheet
python scripts/reason_sheet.py import --sheet <채운 시트> --key <대응표> --out runs/dev/coded
```

시트에 넣는 줄
- 쓸 이유: Q-AI-WHY-USE 줄
- 안 쓸 이유: Q-AI-NOUSE 줄(4-6 보기를 찾았으면 `options_found`에 같이 적음)과 Q-4-7 줄
- 사람 쪽에서 4-3과 안 맞는 칸을 빼듯이, AI가 쓸/안 쓸이라고 한 것과 안 맞는 줄은 넣지 않고 개수만 화면에 찍는다. 쓸 것 같다고 한 기능의 안 쓸 이유·4-7 줄, 안 쓸 것 같다고 한 기능의 쓸 이유 줄이다. 쓸지 안 쓸지 못 가린 기능은 다 넣는다
- 같은 페르소나·회차가 실행 ID만 바뀌어 두 번 들어 있으면(실패 뒤 다시 돌린 기록 등) 종료 코드 4로 멈춘다

판정자가 조건을 모르게 한다
- 시트에는 조건, 페르소나, 반복 번호, 실행 ID를 넣지 않고 줄 순서도 섞는다(`--seed`)
- 줄과 에피소드를 잇는 대응표(`key_*.csv`)는 따로 만든다. 판정자에게는 시트만 준다
- 시트에 조건이 하나뿐이면 경고를 찍는다. 조건별로 시트를 따로 만들면 판정자가 조건을 알게 된다
- 한계: 답 내용에 페르소나 정보가 드러나면("경영학과라서") 조건 1·2인 줄은 짐작할 수 있다

판정자가 채우는 칸
- `code_1`, `code_2`: 두 판정자가 따로 채운다
- `code_final`: 둘이 맞춰 본 뒤 채운다
- 코드는 코드북(#28) 코드를 쓴다. 이유가 아닌 줄은 `-`, 한 줄에 이유가 여럿이면 `;`로 나눈다
- 코드북에 없는 이유는 새 코드를 붙인다. 같은 이유면 같은 새 코드를 쓴다. 사람 코드와 겹치지 않으니 통과 못 한 이유로 센다
- 코드 표기는 가져올 때 맞춘다. 전각 글자, 엑셀이 긴 대시로 바꾼 `-`, 대소문자 차이는 같은 코드로 본다(`n01`과 `N01`). 쉼표로 나눈 칸이 있으면 멈춘다

가져오기는 빈칸이 하나라도 있거나 시트와 대응표의 줄이 안 맞으면 아무것도 쓰지 않고 종료 코드 4로 멈춘다. 두 판정자의 일치율과 Cohen's kappa를 `agreement_*.json`에 남긴다. kappa는 한 줄에 붙인 코드 묶음 전체를 한 라벨로 보고 잰다.

kappa가 0.6에 못 미치면(TRD NFR-07) 판정 기준을 다듬고 다시 판정하도록 멈춘다. 시범 판정처럼 그대로 써야 할 때만 `--accept-low-kappa "사유"`를 붙이고, 사유는 `agreement_*.json`에 남는다.

대응표와 AI 코드 CSV에는 `input_mode`(text/image)와 `model`도 같이 적는다. 계산기는 한 조건 안에 이 값이 섞여 있으면 멈춘다.

## 2. 사람 코드 CSV (정리 담당이 만드는 파일)

| 칸 | 값 |
|---|---|
| respondent_id | 응답자 번호. 이름·연락처는 넣지 않는다 |
| service | snapshot.json의 `service` 값(스냅샷 폴더 이름). `service_name`(화면에 보이는 이름)이 아니다 |
| platform | app 또는 web (폼 3-3) |
| feature_id | F1~F4 (4-3 행 순서) |
| kind | 아래 세 가지 중 하나 |
| code | 코드북 코드. 한 줄에 하나. 그 칸에 답했지만 붙일 코드가 없으면 비워 둔 줄 하나 |
| order | 응답 순서(선택). 포화 계산에 쓴다. 없으면 파일 순서 |

kind는 4-3 답으로 나눈다. 폼 B v2 210행에 "써봤다가 그만둔 사람(4-5)과 안 써본 사람(4-6)은 따로 센다"고 정해져 있다.

| kind | 누구의 어떤 답 | AI와 비교 |
|---|---|---|
| use | 4-3 "자주 쓴다·가끔 쓴다"인 기능의 4-4 서술 | AI 쓸 이유 (D6에서 비교할지 정함) |
| nouse | 4-3 "안 써봤다"인 기능의 4-6 보기와 4-7 서술 | AI 안 쓸 이유. 둘 다 첫인상이라 본 비교 |
| nouse_quit | 4-3 "써봤는데 지금은 안 쓴다"인 기능의 4-5 보기와 4-7 서술 | 같은 AI 안 쓸 이유를 참고로만 대 본다. 요약 판정 수에는 안 넣고 따로 찍는다 |

- 한 응답자가 한 칸에 이유를 셋 말했으면 세 줄이 된다
- 코드가 빈 줄도 사람 수에는 들어간다. 그 칸에 답한 사람을 빠뜨리지 않으려는 것이다
- 폼 운영 규칙대로 4-3과 안 맞는 칸(자주 쓴다면서 4-6에 체크한 칸 등)은 이 파일에 넣지 않는다
- 4-3 "이 서비스에 있는지 모르겠다"인 기능은 이유 문항이 없어서 이 파일에 넣지 않는다
- 11/6 점검 전에는 4-5와 4-6을 nouse 하나로 섞게 적혀 있었다. 폼 규칙에 맞게 고쳤다

## 3. 판정 계산기 (`scripts/score_reasons.py`)

```
python scripts/score_reasons.py --human <사람 코드 CSV> --ai <AI 코드 CSV> --rules configs/rules.draft.json --out runs/dev/scoring --allow-draft
```

- 동결 전 규칙(`frozen: false`)은 `--allow-draft`를 붙여야 돈다. 실제 응답은 동결한 규칙으로만 계산한다(측정 원칙: 기준은 응답을 보기 전에 고정)
- 사람 칸과 AI 칸이 하나도 안 겹치면 멈춘다. service, platform, feature_id 글자가 다른 경우다. 겹치는 칸 수, 한쪽에만 있는 칸 수는 화면과 JSON(`coverage`)에 남는다

출력
- `metrics_*.json`: 실행 ID, 입력 파일 해시, 규칙 전체, 칸별 숫자와 판정, 요약 (FR-10)
- `cells_*.csv`: 조건 x 칸마다 통과율, 재현율, 두 기준점 구간, 판정, 안정 인원
- `reasons_*.csv`: AI가 말한 이유마다 "응답자 15명 중 6명이 같은 이유를 말함" 또는 "응답자 중 이 이유를 말한 사람 없음", 그리고 AI가 놓친 이유. 기말 데모(#35)의 거름망 표로 그대로 쓸 수 있다
- 화면에는 숫자만 찍는다. 규칙이 동결 전이면 화면에 경고를 찍고 JSON에 `rules_frozen: false`로 남긴다

계산 방법
- 판정 칸: 서비스 x 플랫폼 x 기능 x 쓸/안 쓸 (`cell_keys`). 사람이 모자라면 `cell_keys`에서 service를 빼서 두 서비스를 합칠 수 있다(TRD FR-08-04)
- 통과율 = AI가 말한 이유 종류 중 사람도 말한 종류의 비율. 재현율 = 사람이 말한 이유 종류 중 AI도 말한 비율. 몇 번 말했는지가 아니라 종류로 센다
- 사람끼리: 사람을 무작위로 반씩(A, B) 나눠 A가 B를 얼마나 맞히는지 잰다
- AI: 같은 B에 대고 잰다. AI 쪽도 매번 A와 같은 인원만큼 페르소나를 뽑고, 페르소나마다 회차 하나의 이유만 쓴다. 기준(B)과 인원을 둘 다 맞춰야 에피소드 수가 많다는 이유만으로 재현율이 올라가지 않는다. 같은 페르소나의 반복은 서로 다른 사람으로 치지 않는다 [AI 제안, 11/6 점검에서 고침]
- 판정에는 이 값의 중앙값을 쓰고, 에피소드 전체와 사람 전체로 잰 값은 표에 같이 남긴다
- 아무 기능에나 할 말: 같은 조건·서비스·플랫폼·쓸/안 쓸에서 다른 기능의 AI 이유를 같은 방식(같은 인원)으로 뽑아 이 기능의 B에 대고 잰다
- 나누기를 `resamples`번(초안 1,000번) 반복해서 `level`(초안 95%) 구간을 낸다. 시드는 규칙 파일에 있고 칸마다 따로 정해져서 입력 순서가 바뀌어도 같은 결과가 나온다. 나누기, AI 뽑기, 다른 기능 뽑기는 난수를 따로 써서 다른 칸 자료가 이 칸 결과를 흔들지 않는다
- `reason_min_humans`는 이유 표(`reasons_*.csv`)의 통과 표시에만 쓴다. 칸 숫자(통과율, 재현율, 판정)는 사람 1명이라도 말한 이유를 센다

판정 순서 (`method: anchors`)
1. 그 칸에 답한 사람이 `min_humans`(초안 5명) 미만이면 자료 부족
2. AI 이유가 하나도 없으면 계산 불가 (FR-07-06)
3. 통과율이나 재현율의 중앙값이 0이면(AI가 사람 이유를 거의 못 맞힘) 사람에게 물어볼 것
4. 통과율이나 재현율이 아무 기능에나 할 말 구간 위쪽 끝 이하이면 사람에게 물어볼 것
5. 비교할 다른 기능이 없어서 아무 기능에나 할 말 구간이 없으면 참고용까지만 준다
6. 둘 다 사람끼리 구간 아래쪽 끝 이상이면 믿고 써도 됨
7. 나머지는 참고용

4번을 6번보다 먼저 본다. 두 기준점 구간이 겹치는 칸에서는 사람 범위에 들어도 아무 기능에나 할 말과 구별이 안 되기 때문에 믿지 않는 쪽으로 판정한다. [AI 제안]

3번과 5번은 11/6 점검에서 넣었다. 사람끼리 이유가 다 달라서 사람끼리 구간 아래쪽이 0인 칸에서, 비교할 다른 기능까지 없으면 AI가 하나도 못 맞혀도 믿고 써도 됨이 나왔기 때문이다. [AI 제안]

`method: fixed`는 앱 예시 코드(`app/demo_data.py`의 `TRUST_RULES`)와 같은 방식이다. 둘 다 `trust` 이상이면 믿고 써도 됨, 둘 다 `reference` 이상이면 참고용이다. 어느 방법을 본 판정으로 쓸지는 팀이 정한다.

같이 내는 것
- 민감도: `sensitivity`에 적은 규칙(초안: 90% 구간, 고정 60·70·80%)으로 다시 판정해서 판정이 바뀐 칸 수를 센다. 고정값의 참고용 문턱은 trust보다 20%p 낮게 잡았다(TRUST_RULES의 70/50 간격) [AI 제안]
- 조건 0 비교: 조건 1·2·3의 칸마다 통과율이 조건 0(일반 AI)보다 높은지, 같은지, 낮은지 센다
- 안정 인원: 사람을 3명, 5명, 7명…씩 무작위로 뽑아 통과율 평균을 다시 낸다. 그 인원부터 끝까지 평균이 5%p 안에서만 움직이는 가장 작은 인원을 `stable_at`으로 남긴다. 마지막 인원에서만 안정되면 비워 둔다
- 포화: 응답 순서대로 사람마다 새로 나온 이유(기능, 쓸/안 쓸, 코드의 조합) 수를 센다. 하한(초안 15명)을 넘긴 뒤 연속 3명이 1개 이하면 그 서비스는 다 모은 걸로 본다(폼 운영 규칙)

## 4. 코드북 작성자에게 (#28)

- 아무 기능에나 할 말 기준점은 같은 이유가 기능이 달라도 같은 코드를 받아야 뜻이 있다. "필요 없어서"가 공고 저장에서는 N03, 마감 알림에서는 N07처럼 기능마다 다른 코드를 받으면 이 기준점은 늘 0이 되고, 판정이 실제보다 후하게 나온다
- 그래서 기능에 상관없는 이유(필요 없음, 다른 방법으로 해결 등)는 기능 공통 코드로, 그 기능에만 있는 이유는 기능 코드로 나누는 방식을 제안한다 [AI 제안]
- 4-6 보기 5개를 코드북에 그대로 코드로 넣으면 사람 체크와 AI 답을 같은 코드로 맞추기 쉽다 [AI 제안]

```
python -m unittest tests.test_score_reasons tests.test_reason_sheet -v
```

손으로 계산할 수 있는 값(통과율 2/3, 재현율 2/4 등), 판정 순서, 두 기준점이 겹칠 때, 빈칸 검사, kappa, 추출기에서 계산기까지 이어지는 흐름을 확인한다.
