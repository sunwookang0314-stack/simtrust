## 2. 로그 읽는 법

| 로그에 찍힌 말 | 뜻 | 할 일 |
|---|---|---|
| `본 폼 구조 = 11/3 생성 스크립트 구조 (차이 0곳)` | 넣은 링크가 본 폼이 맞다 | 없음 |
| `멈춤: MAIN_FORM_EDIT_URL 이 비어 있다` | 링크를 안 넣었다 | 편집 링크를 넣고 다시 실행 |
| `멈춤: 응답자용 링크` | viewform·forms.gle 링크를 넣었다 | 편집 화면 주소창의 `/edit` 링크로 바꾼다 |
| `멈춤: 구글폼 편집 링크가 아니다` | 링크가 아닌 글이나 다른 사이트 주소를 넣었다 | 편집 화면 주소창 링크를 통째로 복사해 넣는다 |
| `멈춤: 이 링크는 이미 파일럿 사본이다` | 본 폼 자리에 사본 링크를 넣었다 | 본 폼 편집 링크로 바꾼다 |
| `멈춤: 이 폼은 응답이 0건이다` | 시험용으로 만든 다른 v2 폼일 가능성이 크다 | 응답을 받고 있는 그 폼의 편집 링크인지 확인한다 |
| `본 폼이 11/3 생성 스크립트와 N곳 다르다` 다음에 `멈춤: 사본을 만들지 않았다` | v1 폼 링크를 넣었거나, 본 폼을 띄운 뒤 손으로 고친 곳이 있다 | 혼자 `ALLOW_DIFF_FROM_SCRIPT`를 true로 바꾸지 말고 로그 전체를 Claude에게 가져온다 |
| `멈춤: 파일럿 사본이 이미 있다` | 전에 만든 사본이 드라이브에 있다 | 그 링크를 이미 보냈으면 그걸 계속 쓴다. 안 보냈으면 지우고 다시 실행한다 |
| 그 밖의 `멈춤:` | 위에 없는 이유로 멈췄다 | 로그 전체를 가져온다 |
| `사본에 붙어 있던 응답 시트 연결을 끊었다` | 사본이 본 폼 응답 시트를 물고 생겨서 끊었다 | 없음 |
| `사본과 같이 복사된 응답 시트를 휴지통으로 옮겼다` | 본 응답이 들어 있을 수 있는 시트 사본이 생겨서 치웠다 | 열지 말고 드라이브 휴지통에서 영구삭제한다 |
| `사본에 딸려 온 응답 N건을 사본에서 지웠다` | 사본에만 붙은 본 응답을 지웠다. 본 폼 응답은 그대로다 | 없음 |
| `보내지 마라: 검사 N곳 실패` | 사본이 본 폼과 다르거나, 게시가 안 됐거나, 원래 있던 다른 응답 시트가 사본에 붙어 있었다 | 링크를 보내지 말고 로그 전체를 가져온다 |
| `Exception: ...` 같은 빨간 오류 | 중간에 구글 쪽 오류가 났다 | 드라이브에 `[파일럿]` 사본이 생겼으면 지우고, 로그를 가져온다 |
| `검사 통과` | 사본 = 본 폼(제목만 다름), 응답 0건, 시트 연결 없음, 게시됨 | 3번으로 간다 |

## 3. 보내기 전 확인

- 로그의 `파일럿 응답 링크(지인에게 보낼 것, 이 링크 하나만)`를 시크릿 창에서 열어 첫 페이지가 뜨는지만 본다
- [제출]을 누르면 그 응답이 파일럿 CSV에 들어간다. 실수로 끝까지 가지 않게 [다음]도 누르지 않는다
- 로그인 화면이나 권한 요청 화면이 뜨면, 사본 편집 화면의 게시 설정에서 응답자를 "링크가 있는 모든 사용자"로 바꾸고 다시 연다(메뉴 이름은 조금 다를 수 있다)
- 로그의 응답 링크 두 개(파일럿, 본 폼)를 복사해서 Claude에게 준다. 시크릿 창에서 연 것 말고는 더 열지 않는다
- Claude가 두 링크의 응답자 화면 데이터를 읽기만 해서 대조한다. `차이 0곳`과 `파일럿 제목 = "[파일럿] " + 본 폼 제목: 맞음`이 둘 다 나와야 보낸다. 15자 검사(정규식)처럼 스크립트가 못 읽는 것과, 로그인 없이 열리는지가 여기서 확인된다

## 6. 응답을 다 받은 뒤

순서는 응답 수 확인(`count`) → 안 써본 비율(`count --detail`) → 정리 시트 만들기(`make`) → 김승하가 코드 붙이기 → 가져오기(`import`) → 파일럿 값(`params`)이다. 명령은 전부 강선우가 PowerShell에서 직접 친다.

### 6-1. 응답 받기 끄고 CSV 내려받기

1. 편집 화면 맨 위 제목이 `[파일럿]`으로 시작하는지 먼저 본다. 본 폼과 화면이 제목 말고는 똑같아서, 본 폼에서 응답 받기를 끄면 11/18까지 받을 모집이 그 자리에서 멈춘다
2. 제목을 확인한 그 사본의 응답 탭에서 응답 받기를 끈다. 늦게 들어오는 응답을 막는다
3. 같은 응답 탭의 점 세 개 메뉴에서 응답 다운로드(.csv)를 누른다. `[파일럿] 공모전·대회·….csv.zip` 같은 zip이 다운로드 폴더에 내려온다
4. zip을 우클릭해서 압축을 푼다. 같은 이름의 폴더가 생기고 CSV는 그 폴더 안에 있다. CSV 파일 이름이 `[파일럿]`으로 시작하는지 본다
5. CSV와 zip은 다운로드 폴더에 그대로 둔다. `오픈소스` 폴더(저장소, 자료함)로 옮기지 않는다. 저장소에 올라갈 수 있고 Claude 작업 폴더라서다
6. CSV는 아무에게도 넘기지 않는다. 김승하에게는 6-4에서 만드는 정리 시트만 넘긴다(시트에는 서비스·플랫폼과 4-3~4-7 답만 있고 성별·출생연도 같은 기본 정보는 없다). Claude를 포함한 외부 AI에는 원문을 넣지 않는다(폼 첫 페이지 약속, 사전등록 98행)

- `"CSV경로"` 넣는 법: 명령을 메모장에 먼저 붙인다. 압축을 푼 폴더 안의 CSV 파일(폴더 말고 파일)을 우클릭 → 경로로 복사를 누르고, 메모장에서 `"CSV경로"`를 따옴표째 지운 자리에 붙여넣는다(복사한 경로에 따옴표가 같이 붙어 온다). 다 고친 한 줄을 통째로 복사해 PowerShell에 붙여넣는다. 아래 명령의 다른 경로도 같은 식으로 넣는다
- 폴더 경로를 넣으면 `[오류] 입력 파일 없음: --responses`가 뜬다. 압축을 푼 폴더 이름도 `.csv`로 끝나서 헷갈리기 쉽다

- `--service-map`은 이 장의 `count`·`make`·`params`에 꼭 넣는다(`import`에는 없는 옵션이라 붙이면 오류가 난다). 빼면 3-2에서 링커리어·캠퍼스픽이 아닌 서비스를 고른 응답이 안 빠지고 파일럿 숫자에 섞인다(사전등록 97행)

### 6-3. 안 써본 비율 보기

N이 맞을 때만 같은 명령에 `--detail`을 붙여 돌린다.

```
python scripts/form_to_sheet.py count --detail --responses "CSV경로" --service-map "링커리어=linkareer,에브리커리어(캠퍼스픽)=campuspick"
```

- 볼 곳은 `[파일럿 숫자]` 아래 두 줄이다
  - `안 써본 비율: X (기능별 F1 …, F2 …, F3 …, F4 …)`. 4-3 "안 써봤다"만 센 값이다(사전등록 101행). 6-5의 `params`가 같은 값을 다시 찍는다
  - `공통 이유 비율 (참고용 대략값): Y = …`. 6-6에서 코드가 마감까지 안 나왔을 때만 쓴다
- `--detail은 파일럿 사본 폼 응답에만 쓴다` 줄은 늘 찍히는 안내다
- 본 응답 CSV에는 `--detail`을 돌리지 않는다(사전등록 99행). 그래도 돌렸으면 그 숫자는 아무 데도 쓰지 않고 넘기지도 않는다. 그런 일이 있었다는 것만 결과 보고서 한계에 적는다
- 여기 숫자(F1~F4 줄의 `안 써봤다`, `안 써본 비율:`, 대략값)는 6-5·6-6에서 다시 쓴다. 창을 닫았으면 같은 명령을 다시 돌린다(파일럿 CSV라 몇 번 돌려도 된다)

### 6-4. 정리 시트 만들어 김승하에게 보내기

```
python scripts/form_to_sheet.py make --responses "CSV경로" --service-map "링커리어=linkareer,에브리커리어(캠퍼스픽)=campuspick" --out "C:\Users\kangs\Downloads\파일럿코딩"
```

- `--out`을 꼭 이대로 준다. 빼면 시트가 `simtrust-pilot\private\coding`에 생긴다. 커밋은 안 되는 폴더지만 `오픈소스` 폴더 안이다
- 출력 `정리 시트 K줄`(응답자마다 기능 4줄인데 4-3 "이 서비스에 있는지 모르겠다" 칸은 빠지니 3~5명이면 20줄 이하)과 `출력: C:\Users\kangs\Downloads\파일럿코딩/sheet_날짜.csv`를 본다
- 본 응답 CSV로는 `make`를 돌리지 않는다(v2 머지 전, 사전등록 162행). 6-2에서 N을 본 그 CSV만 넣는다
- 김승하에게는 `sheet_날짜.csv` 하나만 보낸다. 같이 생긴 `.summary.json`은 개수만 들어 있어서 안 보내도 된다

김승하에게 같이 전할 것

- `docs/codebook/코딩규칙.md`(#28)대로 `code_1`에 코드를 붙인다. 혼자 붙이면 `code_2`와 `code_final`에 같은 값을 넣는다. 4-7 코드는 코드북 작성자가 붙인다(사전등록 102행, 159행)
- 안 써본 칸(`kind`가 `nouse`)은 `options` 칸에 적힌 4-6 체크도 코드로 같이 적는다. 코드북 출처 칸대로 "쓰기 번거로워 보여서" C03, "나한테 필요 없을 것 같아서" C01, "다른 앱이나 방법으로 해결해서" C02, "딱히 써볼 생각을 안 해봐서" C04다. 4-6 보기와 4-7 코드를 합친 묶음이 파일럿 값의 기준이라서다(사전등록 102행). 4-6 "기타" 체크는 코드로 옮기지 않고, 이유는 4-7 서술에서만 붙인다(102행의 "4-6 보기 4개"에 기타는 안 들어간다)
- 코드가 여럿이면 `;`로 잇고, 붙일 게 없으면 `-`를 쓴다. 빈칸이나 쉼표가 하나라도 있으면 가져오기가 멈춘다. 쓰는 칸(`use`)과 그만둔 칸(`nouse_quit`)도 다 채운다
- 엑셀로 열었으면 저장할 때 파일 형식을 "CSV UTF-8(쉼표로 분리)"로 고른다. 그냥 "CSV"로 저장하면 가져오기에서 `'utf-8' codec can't decode`가 뜬다
- 다 채운 시트는 파일 이름 끝에 `_채움`을 붙여 돌려주고, 코딩할 때 쓴 코드북 CSV도 코드를 안 고쳤어도 같이 돌려준다. 코드북도 엑셀로 열었으면 "CSV UTF-8(쉼표로 분리)"로 저장한다
- 시트는 다른 사람이나 외부 AI에 넘기지 않는다(폼 B 초안 246행, 사전등록 98행). 코드북을 고정한 뒤 지운다

### 6-5. 파일럿 값 뽑기

김승하가 돌려준 `_채움` 시트와 코드북 CSV를 `C:\Users\kangs\Downloads\파일럿코딩`에 넣는다. 김승하를 기다리는 사이 PowerShell을 새로 열었으면 폴더부터 옮긴다.

```
cd C:\Users\kangs\오픈소스\simtrust-pilot
python scripts/form_to_sheet.py import --sheet "채운시트경로" --codebook "코드북경로" --out "C:\Users\kangs\Downloads\파일럿코딩"
```

- `"코드북경로"`에는 김승하가 같이 돌려준 코드북 CSV를 넣고, 아래 `params`에도 같은 파일을 쓴다. 코드북에 없는 코드는 멈추지만, 같은 코드의 scope(공통·기능·기타·제외)가 바뀐 건 안 멈춘다. 공통 이유 비율이 달라지고, 제외로 바뀌거나 제외에서 빠진 코드가 있으면 이유 2개 비율과 코드가 있는 칸 수도 달라진다
- 끝나면 `[가져오기] 시트 K줄 -> 사람 코드 …줄`, `두 정리 담당 일치율 …, kappa …`, `출력: …human_codes_날짜.csv`가 찍힌다. 혼자 붙였으면 보통 kappa가 1.0으로 나오는데 두 사람이 맞춘 값이 아니다
- `시트 K줄`이 6-4 `make`의 `정리 시트 K줄`과 같아야 한다. 다르면 줄이 지워졌거나 다른 시트를 넣은 것이니 멈추고 김승하에게 확인한다
- 멈췄을 때
  - `code_1 빈칸`, `code_2 빈칸`, `쉼표`: 김승하에게 그 칸을 채워 달라고 돌려보낸다. 세 칸 빈칸 수가 모두 K개면 `_채움` 시트가 아니라 원래 빈 시트를 넣은 것이다. 세 칸 빈칸 수가 똑같이 1~2개면 엑셀이 시트 맨 아래에 빈 줄을 남긴 것이니, 엑셀에서 그 줄을 행 삭제하고 다시 저장한다
  - `code_final에 코드북에 없는 코드 N개`: 김승하가 쓴 코드북을 `--codebook`에 넣었는지 본다
  - `'utf-8' codec can't decode`: 시트나 코드북을 엑셀에서 "CSV UTF-8(쉼표로 분리)"로 다시 저장한다
  - `kappa …가 0.6에 못 미친다`: 두 사람이 붙여 일치가 낮거나, 혼자 붙였는데 모든 줄 코드가 같을 때(예: 전부 `-`) 나온다. `--accept-low-kappa "사유"`를 붙여 다시 돌릴지 김민우와 정한다. 사전등록에는 파일럿 kappa 규칙이 없다
  - 그 밖의 `[입력 오류]`: 출력 그대로 Claude에게 가져온다(오류 문구에는 응답 원문이 안 찍힌다)

이제 파일럿 값을 뽑는다. `"사람코드경로"`에는 `import`가 방금 찍은 `human_codes_날짜.csv` 경로를 넣는다.

```
python scripts/form_to_sheet.py params --responses "CSV경로" --human "사람코드경로" --codebook "코드북경로" --service-map "링커리어=linkareer,에브리커리어(캠퍼스픽)=campuspick"
```

- `[파일럿 값] 응답자 M명, 안 써본 칸 A개 중 코드가 있는 칸 B개`: A는 6-3의 `F1 4-3:`~`F4 4-3:` 네 줄에 나온 `안 써봤다` 숫자를 더한 값과 같아야 한다(6-3의 `안 써본 비율:`과 비교하는 게 아니다). 다르면 시트 줄이 빠졌거나 다른 시트를 넣은 것이니 멈춘다. M은 사람 코드가 아니라 CSV에서 다시 센 수라서 이 확인에 못 쓴다. B가 A보다 작으면 안 써본 칸 일부가 `-`이거나 제외 코드만 붙은 칸이라는 뜻이다
- `안 써본 비율 (4-3 "안 써봤다"만)`: 6-3의 `안 써본 비율:` 앞 숫자와 같아야 한다. 다르면 `--service-map`이나 CSV가 다른 것이니 멈춘다
- `공통 이유 비율: … = 공통 코드 …개 / 코드 …개`와 `이유 2개 비율: … (3개 이상인 칸 N개는 2개로 셌다)`: 사전등록 102·103행 방식으로 잰 값이다
- `제외 코드: N개 (판정 계산기처럼 위 두 비율에서 뺐다)`: 코드북 scope가 `제외`인 코드(C07 등)를 안 써본 칸에서 뺀 수다. 판정 계산기와 같은 묶음이 되도록(사전등록 102행, 코딩규칙 R2) `params`가 이미 뺐으니 따로 고칠 것은 없고, 6-6에서 이 숫자를 같이 넘긴다
- 마지막 줄 `시뮬레이션에 넣는 값: --pilot "p_nouse=…,common=…,p_two=…"`를 그대로 넘긴다
