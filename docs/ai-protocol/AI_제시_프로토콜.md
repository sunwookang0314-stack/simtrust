## 3. 화면 입력 방식
- 자동 영어 요약: 끔 [정함]
  - 실행기 설정 `auto_image_description: false`로 `_describe_images`를 막는다
  - 오프라인 테스트와 11/5 Gemini 호출에서 요약 요청이 0번이었다
- 이전 화면 다시 보여주기 수: 1 [정함]. 0은 실행기가 막는다
- 한글은 이스케이프 없이 그대로 보낸다 [정함, 11/6 강선우]. TinyTroupe 기본 동작은 한글을 `\uXXXX`로 바꿔 보내서 입력 토큰이 거의 두 배였다. 실행기가 고친다(`experiments/runner_dev/README.md`)
- see() 묶는 방법: 서비스 캡처 전부를 `see()` 한 번으로 [정함, 1번 ①을 따름]
  - 오프라인 테스트에서 캡처 3장을 한 번에 주면 질문 4개 요청마다 3장씩 들어갔다. 중복은 없었다
- 캡처 없는 기능 처리: 묻지 않고 원시 응답에 `skipped: 없음`으로 남긴다 [정함]. 실행기는 스냅샷의 `missing_features`로 처리한다
- 캡처 파일 이름 규칙: 무작위 16진수 8자리 + `.png` [정함]. 원래 이름과의 대응표는 private/에 둔다. data URI는 쓰지 않는다 [정함]
  - 캡처 경로가 요청마다 글자로 모델 입력에 들어간다. 가짜 화면으로 확인해 보니 `images/fake/app/S1.png`가 질문 4개 요청에 모두 들어 있었다
  - 그래서 파일 이름뿐 아니라 폴더 이름에도 기능 이름이나 세트 이름을 쓰지 않는다. 실행기는 PC 경로 대신 리포 기준 상대 경로를 넘긴다
  - 실행기 설정 `require_random_capture_names: true`로 켜면 규칙에 안 맞는 이름에서 멈춘다
- 1단계 가짜 화면 확인 (`scripts/check_image_input.py`)
  - 요청당 이미지 장수: 3장 묶음을 주면 3장 [확인]
  - 화면 글자를 맞게 말했는지 (11/5, gemini-3.6-flash, 가짜 화면 3장): 화면에만 있는 글자 11개 중 이미지 11개 / 텍스트 0개, 두 방식에 다 있는 글자 15개는 둘 다 15개 [확인]. 모델이 캡처를 실제로 읽는다. gpt-5-mini와 실제 캡처로는 3단계에서 다시 잰다
- 고른 것 (3단계): 이미지 / 텍스트 [측정 대기]
- 이유 (실측 숫자): [측정 대기]

## 4. 캡처로 안 드러나는 기능 (강선우가 정한 내용)
- 웹/앱: 두 플랫폼을 다 쓴다. 가상 사용자 한 명한테는 한 플랫폼 화면만 준다 [정함]
- 계정: 기존 계정이고, 예전 기록(대외활동 스크랩, 채널 팔로우)은 11/1에 지웠다 [정함]
  - 참고 초안 4번에는 "서비스마다 새 계정"으로 적혀 있다. 실제로는 기존 계정을 정리해서 찍었다
- 마감 알림 [정함]
  - 앱 플랫폼: 링커리어 "스크랩 공고 알림: 마감일 D-1일 때 알림" 설정과 알림이 온 알림함, 캠퍼스픽 "마감 임박 알림: 마감 D-3 알림" 설정과 알림함
  - 웹 플랫폼: 링커리어는 알림이 온 웹 알림함·스크랩 달력·앱 설치 배너. 캠퍼스픽은 웹에 알림 페이지가 없어서 마감임박순 정렬 화면으로 대신한다
- 추천 공고 목록: 두 플랫폼 모두 인기·추천 목록. 개인 맞춤 추천은 두 서비스 모두 안 보였다 [정함]
- 검색어 세트: 인턴 세트 (11/3 정함) [정함]
- 없는 기능: 11/2 캡처 기준으로 두 플랫폼 모두 해당 없음 [정함]
- 한계로 적는 것
  - 앱 캡처는 안드로이드라 아이폰 앱과 메뉴 위치가 다를 수 있다
  - 웹 플랫폼의 캠퍼스픽 마감 알림 칸은 기능 자체가 아니라 가장 가까운 화면이다

## 6. 에피소드
- 서비스·플랫폼당 한 에피소드, 에피소드마다 새 에이전트 [정함]. 두 번째 에피소드에 첫 번째 기억이 안 들어가는 것을 테스트로 확인했다
- 질문 순서: (b) [정함, 11/6 강선우]. 사람 폼 순서(4-3, 4-4, 4-6, 4-7)와 같고 4-7을 글자 그대로 줄 수 있다
  1. 시작 안내
  2. 섹션 안내 + 캡처
  3. Q-AI-USE: 기능마다 쓸 것 같다 / 안 쓸 것 같다
  4. Q-AI-WHY-USE: 쓸 것 같다고 한 기능의 이유
  5. Q-AI-NOUSE: 안 쓸 것 같다고 한 기능의 4-6 보기
  6. Q-4-7: 폼 4-7 문항 그대로
  - 쓸 것 같은 기능이 없으면 4를, 안 쓸 것 같은 기능이 없으면 5를 건너뛴다. 실행기가 Q-AI-USE 답에서 어느 기능 답인지 못 가리면 4와 5를 다 묻는다
- AI에게 4-8(불편했던 점)·4-9(바뀌었으면 하는 점)는 묻지 않는다 [정함, 11/6 강선우, D2]. 4-8은 헤맨 경험을 묻는데 AI는 서비스를 써 본 적이 없고, 물으면 불편 유형 코드북이 하나 더 필요하다. 사람의 4-8·4-9 응답은 데모 자료로만 쓴다
- 조건: 0·1·2만 돈다. 조건 3(후기 자료)은 이번 학기에 하지 않는다 [정함, 11/6 강선우]. 공식 검색 API가 결과 저장과 AI 활용을 막아서 TRD 조건(공식 API, 크롤링 없음)으로는 후기 자료를 만들 수 없다(`조건3_후기_출처_조사.md` 선택지 1)
- 기능 순서: 4-3 행 순서 그대로 [정함]
- 기능 목록·질문 파일 위치: `docs/ai-protocol/features.txt`, `docs/ai-protocol/options_4-6.txt`, `docs/ai-protocol/questions/{질문 ID}.txt` [정함]
  - 11/6에 `experiments/runner_dev/protocol/`에서 옮겼다. 실행 설정은 `protocol_dir: docs/ai-protocol`, `protocol_version: v0.1`

## 8. [AI 대응] 문구
### 시작 안내 (폼 설명 대응) [정함, 11/6 강선우]
> 공모전·대회·인턴·취업 공고 서비스에서 어떤 기능을 왜 쓰고 왜 안 쓰는지 여쭤보려고 합니다. 정해진 답은 없으니 생각나는 대로 답해 주시면 됩니다. 이 서비스는 오늘 처음 보는 서비스입니다. 모든 답은 한국어로 해 주세요.

- 폼 제목과 설명이 11/3에 "공모전·대회·인턴·취업"으로 바뀌어서 시작 안내도 맞췄다. 전에는 "대외활동·공모전·취업"이었다. 그대로 두면 AI와 사람이 받는 대상이 달라진다

### 섹션 4 안내 (AI용) [정함]
> 아래는 {서비스 이름} {앱/웹사이트} 화면입니다. 화면을 살펴본 뒤 질문에 답해 주세요.

- 참고 초안은 "앱 화면"이었다. 웹 플랫폼도 돌려서 플랫폼 자리를 폼 3-3 보기("앱", "웹사이트")로 채우게 했다
- 서비스 이름은 캡처에 실제로 뜨는 이름을 스냅샷 `service_name`에 적는다
