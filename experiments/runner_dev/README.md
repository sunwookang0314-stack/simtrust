# AI 실행기 1단계 (scripts/run_simulation.py)

`docs/work-orders/kim-minwoo/AI실행기.md`(11/1 개정판)의 1단계 뼈대다. 가짜 화면, 임시 페르소나, 무료 Gemini로 명령 한 줄을 치면
원시 응답, 실행 기록, 숫자 요약이 나온다.

질문 흐름은 아직 v4 과제형(과제마다 화면 하나를 보여주고 한 번 행동)이다. 2단계에서 폼 B 질문 순서(프로토콜 6번)로 바꾼다. 비용 상한, 캐시, 실행 기록, 종료 코드는 그대로 쓴다.

## 실행

```powershell
.\.venv\Scripts\python.exe scripts\use_provider.py gemini
.\.venv\Scripts\python.exe scripts\run_simulation.py --service fake --platform app --condition 2 --repeat 1 --seed 1 `
    --config configs\simulation.dev.json --limit-personas 1
```

- `--platform`은 `app` 또는 `web`이다. 앱과 웹은 화면이 달라서 스냅샷을 `{snapshot_root}/{서비스}/{플랫폼}/snapshot.json`에 따로 둔다. 에이전트 하나에는 한 플랫폼 화면만 준다.
- `--config`를 안 주면 `configs/simulation.json`을 읽는다. 본실험용 값(화면 입력 방식, 비용 상한 등)이 아직 안 정해져서 이 파일은 만들지 않았다.
- `--limit-personas`는 시범 실행용이다. 페르소나 폴더에서 앞에서부터 N명만 쓴다. 조건 0은 슬롯 10개 중 앞의 N개만 돈다.

출력 위치는 실행 설정에서 정한다. 개발 설정은 전부 `runs/dev/` 아래로 보내서 공개 폴더(`data/virtual/`)를 더럽히지 않는다.

| 파일 | 내용 |
|---|---|
| `runs/dev/raw_responses.jsonl` | 원시 응답. 한 줄 = 한 에피소드(서비스 x 플랫폼 x 조건 x 페르소나 x 회차). 성공한 에피소드만 쓴다 |
| `runs/dev/meta/{run_id}.json` | 실행 기록. TRD 7장 칸 + platform, protocol_version, snapshot_version, 행동 잘림 횟수 등. 실패한 에피소드도 사유와 함께 남는다 |
| `runs/dev/meta/{batch_id}.summary.json` | 숫자 요약. 화면에도 같은 숫자만 찍는다 |
| `runs/dev/cache/{서비스}_{플랫폼}_c{조건}_{모델}/{페르소나}_r{회차}.json` | API 캐시. 조건 0은 페르소나 자리에 슬롯 |

종료 코드는 TRD 6장 표를 따른다. 0 정상, 1 사용법 오류·입력 파일 없음, 2 설정 불일치·인증, 3 비용 상한, 4 입력 검증 실패, 5 API 실패.

- 인증 오류, 모델 없음(2)과 비용 상한(3)은 다음 에피소드도 같은 이유로 막혀서 그 자리에서 멈춘다.
- 그 밖의 실패(빈 응답, 일시 오류가 끝내 안 풀림)는 실행 기록에 남기고 다음 에피소드로 간다. 종료 코드 5는 전부 실패했거나 실패율이 5%(NFR-06)를 넘을 때만 낸다.

## 오프라인 테스트

API 키 없이 돈다. TinyTroupe의 실제 호출 함수만 가짜로 바꾸고 나머지는 그대로 쓴다.

```
python -m unittest tests.test_run_simulation -v
```

17개를 확인한다.

- 같은 캐시로 다시 돌리면 API를 안 부르고 같은 결과가 나온다. 회차마다 캐시가 따로다
- 앱·웹이 각자 스냅샷과 캐시를 쓴다
- 두 번째 에피소드에 첫 번째 에피소드의 답과 페르소나가 안 들어간다
- 행동 목록이 상한보다 길면 잘린 횟수가 실행 기록과 숫자 요약에 찍힌다
- 조건 0은 슬롯 C0-01~C0-10, 조건 0·1 이름은 `참여자`, 조건 1에서 이름·거주지가 빠진다
- 기능 설명이 AI 입력에 안 들어간다
- 비용 상한(3). 이전 실행 토큰까지 합쳐서 세고, 제공자가 다른 기록은 뺀다
- 인증 오류와 모델 없음은 재시도 없이 2. 키가 비었거나 제공자가 어긋나도 2
- 빈 응답은 캐시를 지우고 다시 시도한 뒤 5
- 에피소드 하나가 실패해도 다음 에피소드로 넘어간다. 20개 중 1개 실패(5%)면 0, 2개 중 1개 실패면 5
- 입력 오류(1, 4)

## 작업지시서를 따라 정한 것

역할(2026-11-01): 실행기와 추출(IF-06)은 김민우가 맡는다.

- 행동 상한은 TinyTroupe 기본값 15를 쓴다. 3으로 낮추면 [THINK, THINK, TALK, DONE]이 [THINK, THINK, DONE]으로 잘려서 답이 사라진다. TinyTroupe는 자를 때 로그를 안 남겨서 실행기가 센다.
- 비용 상한은 같은 실행 기록 폴더(`meta_dir`)에 남은 이전 에피소드 토큰까지 합쳐서 센다. 명령은 서비스 x 플랫폼 x 조건으로 나눠 돌아서, 명령마다 따로 세면 상한의 몇 배를 쓸 수 있다.
- 에피소드마다 새 에이전트를 만들고 TinyTroupe 에이전트 등록을 비운다.
- 조건 0·1 에이전트 이름은 실행 설정 `neutral_agent_name`으로 받는다. 개발 설정은 v0.1 참고 초안 7번 제안대로 `참여자`다. 프로토콜 v0.1에서 확정한다.

## 구현하면서 정한 것

- run_id는 에피소드마다 하나다. 명령 한 번은 batch_id로 묶는다.
- 비용 상한은 다음 실제 호출 직전에 확인한다. 그래서 마지막 호출 하나만큼은 상한을 넘을 수 있다. 캐시 응답은 세지 않는다.
- 누적 토큰을 셀 때 제공자가 다른 기록은 뺀다. 무료 Gemini로 돌린 개발 기록은 유료 예산에서 돈이 나가지 않기 때문이다. 이전 기록 중 하나라도 못 읽으면 누적을 셀 수 없어서 종료 코드 4로 멈춘다.
- seed는 기록만 한다. TinyTroupe가 API에 seed를 넘기지 않는다.
- TinyTroupe 안에서 예상 못 한 오류가 나면 실행 기록에 traceback을 남기고 그 에피소드를 실패로 친다.
- 과제 지시 문구(`task_prompt_template`)는 개발 설정 파일에 넣은 임시 문구다. 2단계에서 프로토콜 문구 파일로 바꾼다.

## 아직 확인 못 한 것

- 새 코드로 실제 Gemini 정상 실행 (위 503)
- 비용 상한(3)은 오프라인 테스트로만 확인했다.
- TinyTroupe가 실행한 폴더에 `tinytroupe.*.log`를 남기고, 여기에 프롬프트 전문이 들어간다. `*.log`라 커밋은 안 되지만 실제 캡처로 시범 실행하기 전에 로그 위치를 옮겨야 한다(#10).
- 이미지 입력(`input_mode: image`). 코드 경로만 있고 돌려 보지 않았다(#8).

## 테스트하다 본 것

TinyTroupe는 한글을 `\uXXXX` 형태로 바꿔서 모델에 보낸다. 페르소나는 `agent/tiny_person.py:319`의 `json.dumps(..., indent=4)`, 메시지(화면 설명, 과제 문구 포함)는 `agent/action_generator.py:125`의 `json.dumps(msg["content"])`가 `ensure_ascii` 기본값으로 직렬화하기 때문이다. 토큰 수와 응답 품질에 얼마나 영향이 있는지는 아직 재지 않았다. 고치면 캐시 키가 바뀌므로 본실험 전에 정해야 한다.
