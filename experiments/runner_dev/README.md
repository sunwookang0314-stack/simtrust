# AI 실행기 개발용 자료 (scripts/run_simulation.py)

`docs/work-orders/kim-minwoo/AI실행기.md`(11/1 개정판)의 1·2단계를 여기서 개발한다. 가짜 화면, 임시 페르소나, 무료 Gemini로 명령 한 줄을 치면 폼 B 질문 순서대로 AI에게 묻고 원시 응답, 실행 기록, 숫자 요약을 남긴다.

| 폴더·파일 | 내용 |
|---|---|
| `snapshots/fake/{app,web}/snapshot.json` | 가짜 스냅샷. 앱과 웹을 따로 둔다 |
| `images/fake/{app,web}/` | 가짜 화면 PNG 3장씩과 채점용 글자 목록(`labels.json`). `make_fake_screens.py`로 만든다 |
| `protocol/` | 개발용 질문 파일. 프로토콜 v0.1이 정해지면 `docs/ai-protocol/`로 옮긴다 |

## 실행

```powershell
.\.venv\Scripts\python.exe scripts\use_provider.py gemini
.\.venv\Scripts\python.exe scripts\run_simulation.py --service fake --platform app --condition 2 --repeat 1 --seed 1 `
    --config configs\simulation.dev.json --limit-personas 1
```

- `--platform`은 `app` 또는 `web`이다. 스냅샷은 `{snapshot_root}/{서비스}/{플랫폼}/snapshot.json`, 캡처는 `{images_root}/{서비스}/{플랫폼}/`에 둔다. 에이전트 하나에는 한 플랫폼 화면만 준다.
- `--config`를 안 주면 `configs/simulation.json`을 읽는다. 본실험용 값(화면 입력 방식, 비용 상한 등)이 아직 안 정해져서 이 파일은 만들지 않았다.
- `--limit-personas`는 시범 실행용이다. 페르소나 폴더에서 앞에서부터 N명만 쓴다. 조건 0은 슬롯 10개 중 앞의 N개만 돈다.

## 질문 흐름 (2단계)

프로토콜 6번 (b)와 v0.1 참고 초안 6번 순서를 따른다.

1. 시작 안내 (`START.txt`)
2. 섹션 안내와 캡처 (`SECTION4.txt`). 캡처는 `see()` 한 번에 묶어서 준다(①)
3. Q-AI-USE: 기능마다 쓸 것 같다 / 안 쓸 것 같다
4. Q-AI-WHY-USE: 쓸 것 같은 기능이 하나도 없으면 건너뛴다
5. Q-AI-NOUSE: 4-6 보기를 준다. 안 쓸 것 같은 기능이 하나도 없으면 건너뛴다
6. Q-4-7: 폼 문구 그대로. 폼에서 필수라 늘 묻는다

- 건너뛸지는 Q-AI-USE 답을 실행 중에 간단히 읽어서 정한다. 어느 기능 답인지 못 가리면 두 꼬리 질문을 다 묻는다. 원문은 다 남기고 정식 정리는 추출 단계(IF-06)가 한다.
- 스냅샷의 `missing_features`에 적힌 기능은 묻지 않고 원시 응답에 `skipped: 없음`으로 남긴다.
- 질문 순서 (a)와 기능별 제시(②)는 아직 안 짰다. (a)는 강선우 결정, ②는 3단계 실측 뒤에 정한다.

### 질문 파일 (`protocol/`)

| 파일 | 출처 |
|---|---|
| `features.txt` (한 줄에 기능 하나, F번호와 이름을 세로 막대로 구분) | 배포된 폼 4-3 행. 생성 스크립트(`docs/form-b/SimTrust-폼B-v2-생성.gs`)와 한 글자도 다르지 않은 것을 11/5에 확인했다 |
| `options_4-6.txt` | 배포된 폼 4-6 보기. 위와 같이 확인했다 |
| `questions/Q-4-7.txt` | 배포된 폼 4-7 제목과 설명. 위와 같이 확인했다 |
| `questions/START.txt`, `SECTION4.txt`, `Q-AI-USE.txt`, `Q-AI-WHY-USE.txt`, `Q-AI-NOUSE.txt` | v0.1 참고 초안(강선우)의 제안 문구를 그대로 옮겼다. 확정 전이다 |

- `SECTION4.txt`의 `{service_name}`은 스냅샷의 `service_name`, `{platform_label}`은 폼 3-3 보기("앱", "웹사이트")로 채운다.
- 파일은 줄바꿈을 LF로 읽는다. 윈도에서 git이 CRLF로 받아도 폼 문구와 글자가 같아야 하기 때문이다.

## 출력

출력 위치는 실행 설정에서 정한다. 개발 설정은 전부 `runs/dev/` 아래로 보내서 공개 폴더(`data/virtual/`)를 더럽히지 않는다.

| 파일 | 내용 |
|---|---|
| `runs/dev/raw_responses.jsonl` | 원시 응답. 한 줄 = 한 에피소드(서비스 x 플랫폼 x 조건 x 페르소나 x 회차). 질문마다 question_id, feature_id, 들어간 캡처, THINK, TALK, 행동 원문. 성공한 에피소드만 쓴다 |
| `runs/dev/meta/{run_id}.json` | 실행 기록. TRD 7장 칸 + platform, protocol_version, snapshot_version, 행동 잘림 횟수, 물은 질문, 요청별 이미지 장수 등. 실패한 에피소드도 사유와 함께 남는다 |
| `runs/dev/meta/{batch_id}.summary.json` | 숫자 요약. 화면에도 같은 숫자만 찍는다 |
| `runs/dev/cache/{서비스}_{플랫폼}_c{조건}_{모델}/{페르소나}_r{회차}.json` | API 캐시. 조건 0은 페르소나 자리에 슬롯 |
| `runs/dev/logs/tinytroupe.{batch_id}.log` | TinyTroupe 로그. 프롬프트 전문이 들어가서 실행 폴더가 아니라 여기로 옮긴다 |

종료 코드는 TRD 6장 표를 따른다. 0 정상, 1 사용법 오류·입력 파일 없음, 2 설정 불일치·인증, 3 비용 상한, 4 입력 검증 실패, 5 API 실패.

- 인증 오류, 모델 없음(2)과 비용 상한(3)은 다음 에피소드도 같은 이유로 막혀서 그 자리에서 멈춘다.
- 그 밖의 실패(빈 응답, 일시 오류가 끝내 안 풀림)는 실행 기록에 남기고 다음 에피소드로 간다. 종료 코드 5는 전부 실패했거나 실패율이 5%(NFR-06)를 넘을 때만 낸다.

## 이미지 입력 (프로토콜 3번)

- 자동 영어 요약(`_describe_images`)은 실행 설정 `auto_image_description: false`로 끈다.
- 이전 화면 다시 보여주기 수는 `max_image_stimuli_to_recall`로 받는다. 1을 쓴다. 0이면 TinyTroupe가 전부 다시 넣어서 막았다.
- 캡처 경로가 글자로 모델 입력에 들어간다. 그래서 PC 경로 대신 리포 기준 상대 경로를 넘긴다. 실제 캡처는 `require_random_capture_names: true`로 켜서 파일 이름이 무작위 16진수 8자리 + `.png`가 아니면 멈춘다. 개발용 가짜 화면은 `S1.png` 같은 이름이라 끈다.
- 오프라인 테스트에서 캡처 3장을 `see()` 한 번에 주면 질문 4개 요청마다 3장씩 들어갔다. 중복은 없었다.

`scripts/check_image_input.py`는 가짜 화면을 이미지로 줄 때와 텍스트로 줄 때 AI가 화면 글자를 맞게 말하는지 비교하는 단독 스크립트다(1-b). 결과는 `runs/dev/image_check/`에 남는다.

API 키 없이 돈다. TinyTroupe의 실제 호출 함수만 가짜로 바꾸고 나머지는 그대로 쓴다.

```
python -m unittest tests.test_run_simulation -v
```

28개를 확인한다.

- 질문 흐름: 질문 4개가 순서대로 가고, 꼬리 질문은 필요 없으면 건너뛰고, 캡처 없는 기능은 묻지 않고 기록한다
- 폼 문구(4-7, 4-6 보기, 기능 이름)가 그대로 가고 `{자리}`가 남지 않는다. 기능 설명은 안 들어간다
- 이미지 모드: 질문마다 캡처 3장, 자동 요약 호출 없음. 무작위 파일 이름을 켜면 `S1.png`에서 멈춘다
- TinyTroupe 로그가 설정한 폴더로 옮겨진다
- 같은 캐시로 다시 돌리면 API를 안 부르고 같은 결과. 회차마다, 플랫폼마다 캐시가 따로다
- 두 번째 에피소드에 첫 번째 에피소드의 답과 페르소나가 안 들어간다
- 조건 0은 슬롯 C0-01~C0-10, 조건 0·1 이름은 `참여자`, 조건 1에서 이름·거주지가 빠진다
- 행동 잘림 횟수, 비용 상한(이전 실행 누적), 인증 오류와 모델 없음(2), 빈 응답(5), 실패 뒤 계속, 입력 오류(1, 4)
- 실행 중 쓸/안 쓸 판별(parse_use_answers)
- 이미지 확인 스크립트(1-b)

## 작업지시서를 따라 정한 것

역할(2026-11-01): 실행기와 추출(IF-06)은 김민우가 맡는다.

- 행동 상한은 TinyTroupe 기본값 15를 쓴다. 3으로 낮추면 [THINK, THINK, TALK, DONE]이 [THINK, THINK, DONE]으로 잘려서 답이 사라진다. TinyTroupe는 자를 때 로그를 안 남겨서 실행기가 센다.
- 비용 상한은 같은 실행 기록 폴더(`meta_dir`)에 남은 이전 에피소드 토큰까지 합쳐서 센다. 명령은 서비스 x 플랫폼 x 조건으로 나눠 돌아서, 명령마다 따로 세면 상한의 몇 배를 쓸 수 있다.
- 에피소드마다 새 에이전트를 만들고 TinyTroupe 에이전트 등록을 비운다.
- 조건 0·1 에이전트 이름은 실행 설정 `neutral_agent_name`으로 받는다. 개발 설정은 v0.1 참고 초안 7번 제안대로 `참여자`다.

## 구현하면서 정한 것

- run_id는 에피소드마다 하나다. 명령 한 번은 batch_id로 묶는다.
- 비용 상한은 다음 실제 호출 직전에 확인한다. 그래서 마지막 호출 하나만큼은 상한을 넘을 수 있다. 캐시 응답은 세지 않는다.
- 누적 토큰을 셀 때 제공자가 다른 기록은 뺀다. 무료 Gemini로 돌린 개발 기록은 유료 예산에서 돈이 나가지 않기 때문이다. 이전 기록 중 하나라도 못 읽으면 누적을 셀 수 없어서 종료 코드 4로 멈춘다.
- seed는 기록만 한다. TinyTroupe가 API에 seed를 넘기지 않는다.
- 텍스트 모드는 화면 설명을 "화면 1: …"처럼 순서 번호만 붙여 한 번에 준다. S번호는 쓰지 않는다.
- (b)에서는 질문 하나가 기능 여럿을 묻기 때문에 질문마다 feature_id를 빈 값으로 둔다.

TinyTroupe는 한글을 `\uXXXX` 형태로 바꿔서 모델에 보낸다. 페르소나는 `agent/tiny_person.py:319`의 `json.dumps(..., indent=4)`, 메시지(화면 설명, 질문 문구 포함)는 `agent/action_generator.py:125`의 `json.dumps(msg["content"])`가 `ensure_ascii` 기본값으로 직렬화하기 때문이다. 토큰 수와 응답 품질에 얼마나 영향이 있는지는 아직 재지 않았다. 고치면 캐시 키가 바뀌므로 본실험 전에 정해야 한다.
