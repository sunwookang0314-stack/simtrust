## 가짜 설정

- 서비스 2곳(linkareer, campuspick) x 응답자 40명, 기능 4개 (폼 B v2 4-3 행)
- 이유 코드는 코드북 v0.1(`docs/codebook/코드북_초안.csv`)을 그대로 쓴다. 이름도 코드북 `name` 칸에서 온다
- 사람 이유: 안 쓸 이유의 60%가 공통 이유(사람 수 시뮬레이션의 common60과 같은 비율), 나머지는 기능 이유. 기타(C98·U98) 3%, 기능과 상관없는 이유(C07·U05) 2%
- 가짜 사람은 C06, U04와 기능 코드가 3개 이상인 기능의 마지막 코드(F3-05, F4-03, F4-U03)를 안 말한다고 정했다. 반만 맞는 모델이 이 코드를 대서 "응답자 중 이 이유를 말한 사람 없음"이 나온다
- AI는 서비스·플랫폼마다 10명(조건 0은 슬롯, 조건 2는 페르소나) x 반복 3번 = 답 30개. 앱·웹을 합친 칸에는 60개가 들어간다. 계산기는 반복 3번을 한 사람으로 묶는다

| 파일 이름 | 흉내 낸 것 |
|---|---|
| `model_a` | 조건 0. 사람과 같은 분포로 이유를 대는 모델 |
| `model_b` | 조건 0. 절반은 사람이 안 말하는 이유를 대는 모델 |
| `model_c` | 조건 0. 4-6 보기에 있는 흔한 이유(C01~C04)만 대는 모델 |
| `persona` | 조건 2. 바탕 모델 하나에 페르소나 10명(P01~P10)을 씌운 것. 페르소나마다 자주 대는 이유가 조금씩 다르다 |

- 기말 데모에서 `model_a/b/c`는 GPT·Claude·Gemini 자리이고, `persona`는 바탕 모델 + 페르소나 자리다. 어느 파일이 어느 모델인지는 의미 없다
- 가짜라서 모델끼리 판정 차이나 페르소나 효과의 크기는 의미 없다

## 파일

| 파일 | 내용 |
|---|---|
| `out/reasons_{model_a,model_b,model_c,persona}.csv` | 이유 한 줄씩. #35 화면의 이유 목록 |
| `out/cells_{model_a,model_b,model_c,persona}.csv` | 칸(서비스 x 기능 x 쓸/안 쓸)마다 숫자와 판정 |
| `out/summary.json` | 모델별 안 쓸 이유 칸 판정 수 |

코드북은 따로 복사하지 않는다. 코드 이름과 정의는 `docs/codebook/코드북_초안.csv`를 읽는다.

## reasons 표 칸

| 칸 | 뜻 |
|---|---|
| scope | `main`이면 본 칸, `platform_ref`면 플랫폼별 참고 칸. 화면에는 `main`만 써도 된다 |
| condition | 0이면 페르소나 없음, 2면 페르소나 AI |
| service, feature_id | 서비스, 기능(F1~F4) |
| platform | `*`면 앱·웹을 합친 칸 |
| kind | `use` 쓸 이유, `nouse` 안 써본 사람의 안 쓸 이유, `nouse_quit` 그만둔 사람의 안 쓸 이유(참고) |
| type | `ai_reason`은 AI가 말한 이유, `missed`는 사람은 말했는데 AI가 안 말한 이유 |
| code, name | 코드북 코드와 이름. 사람 쪽 기타는 `C98@사람`처럼 붙어서 AI 기타와 겹치지 않는다 |
| common | Y면 어느 기능에나 나오는 공통 이유 |
| ai_episodes_with_code / ai_episodes | AI 답 몇 개 중 몇 개가 이 이유를 말했나 |
| ai_personas, ai_persona_ids | 이 이유를 말한 AI 사람 수와 번호(`app:P03;web:P07` 꼴). 반복 3번은 한 사람이고, 같은 번호라도 앱과 웹은 다른 사람이다. 판정에는 안 쓴다 |
| human_count / n_humans | 응답자 몇 명 중 몇 명이 같은 이유를 말했나 |
| passed | Y면 응답자 중 같은 이유를 말한 사람이 있다 (초안 기준 1명 이상) |
| basis | 화면에 그대로 쓸 근거 문장. "응답자 14명 중 6명이 같은 이유를 말함" |

## cells 표에서 쓸 칸

| 칸 | 뜻 |
|---|---|
| n_humans | 그 칸에 답한 응답자 수 |
| precision, recall | 통과율, 재현율 |
| precision_nocommon, recall_nocommon | 공통 이유를 빼고 잰 통과율, 재현율. 판정에는 안 쓴다 |
| verdict | 믿고 써도 됨 / 참고용 / 사람에게 물어볼 것 / 자료 부족 / 계산 불가 |
| human_precision_low, human_precision_high | 사람끼리 범위 |
| floor_precision_low, floor_precision_high | 아무 기능에나 할 말 범위 |
| dist, rank | 분포 유사도(1이면 이유별 비율이 같음), 순위 일치(1이면 많이 말한 순서가 같음). 사전등록 v1.1 추가안 |
| perm_p_dist, perm_p_rank | AI와 사람 이유 분포가 다르다는 증거(순열 검정 p). 작을수록 다르다 |
| coverage, coverage_need | 사람 이유를 몇 % 봤는지 추정값, 90%까지 필요한 그 칸 응답자 수. 판정에는 안 쓴다 |
| human_equiv_n | AI 답이 사람 몇 명분인지(분포 유사도 기준). 판정에는 안 쓴다 |

## #35 화면으로 옮기는 법 [제안]

1. 이유 목록: reasons에서 `scope=main`, `type=ai_reason`인 줄의 `name`과 `basis`. `passed`가 Y면 "믿을 만함", N이면 "믿기 어려움"
2. AI가 놓친 이유: `type=missed`인 줄
3. 기능마다 판정: cells의 `verdict`
4. AI끼리 비교: 네 파일에서 같은 service, feature_id, kind, code를 맞춰 보면 넷 다 말한 이유와 하나만 말한 이유가 나온다
5. 누가 말했는지: `ai_persona_ids`를 `;`로 나누면 페르소나 원에 표시할 번호가 나온다

## 읽을 때 주의

- 안 쓸 이유 칸은 대부분 "사람에게 물어볼 것"이다. 공통 이유가 많아서 다른 기능 답(아무 기능에나 할 말)과 구별이 안 되기 때문이다. AI 답이 칸마다 60개라 AI가 거의 모든 이유를 한 번씩은 말하는 것도 영향이 있다. 이 규칙이 사람이 적을 때 너무 엄격하다는 것은 사람 수 시뮬레이션에도 나왔다
- 판정 규칙은 아직 동결 전(`configs/rules.draft.json`)이라 v2 시뮬레이션으로 규칙이 정해지면 판정 결과가 바뀔 수 있다. 표 모양은 그대로다
- 서술 답은 "마감 알림: 알림이 너무 잦음에 해당하는 가짜 답입니다." 같은 가짜 문장이라 정리 시트는 견본에 넣지 않았다
