## 무엇을 하나

1. 판정 규칙마다, 합격 기준을 넘는 최소 인원을 두 구성(서비스 하나, 두 서비스 합친 것)에서 찾는다. 기준은 v1 1장 넷에 v1.1의 순위 뒤집힌 AI 기준을 더한 다섯이고, v1 기준 넷으로 잰 최소 인원도 같이 낸다
2. 고르는 법(v1 2장, v1.1 3장)대로 규칙을 하나 고르고, 서비스별 판정 인원 T(40명과 고른 규칙의 서비스 하나 최소 인원 중 큰 값)를 낸다
   - 1단계: 다섯 기준을 넘고 합친 구성 최소 인원이 60명 이하인 규칙 중에서 고른다
   - 2단계: 그런 규칙이 없으면 v1 기준 넷으로 고르고, 순위 뒤집힌 AI는 한계로 적는다
3. 사람 같은 AI 시나리오에서 칸마다 커버리지 추정값과 실제값, 90%까지 필요한 전체 응답자 수 추정을 인원별로 모은다 (판정에 안 씀)

## 합격 기준 (사전등록 v1 1장, v1.1 1장)

가정마다 아래를 모두 넘어야 그 인원에서 합격이다. 가정이 여러 개면 가장 나쁜 경우에서도 넘어야 하고, 점추정 그대로 댄다.

| 기준 | 값 |
|---|---|
| 사람 같은 AI를 "믿고 써도 됨"으로 판정 | 80% 이상 |
| 반만 맞는 AI를 "믿고 써도 됨"으로 판정 | 10% 이하 |
| 공통 이유만 말하는 AI를 "믿고 써도 됨"으로 판정 | 5% 이하 |
| 자료 부족 칸 (세 AI 시나리오 중 가장 큰 값, 11/8 변경 기록) | 5% 이하 |
| 순위 뒤집힌 AI를 "믿고 써도 됨"으로 판정 (v1.1) | 10% 이하 |

최소 인원은 그 인원과 그보다 큰 시뮬레이션 인원 전부에서 합격하는 가장 작은 인원이다.

## 후보 규칙

`main`(두 기준점 95%), `anchors_90`, `gate_fixed_70`(기준점 검사 + 고정 70%, 정의는 사전등록 2장), `fixed_80`, `fixed_70`, `fixed_60`, 그리고 v1.1에서 더한 `main_dist`(main + 분포 유사도 순열 검정), `main_rank`(main + 순위 일치 순열 검정), v1.2에서 더한 `ladder_50`(가짜 AI 사다리: 그 칸 사람 답으로 만든 나쁜 가짜를 전부 이기고 사람과 다르다는 증거가 없어야 믿음). 모두 `configs/rules.draft.json`에 있다.

- `ladder_50`은 공통 이유가 무엇인지 알아야 해서 시뮬레이션이 공통 코드 넷(C1~C4)을 코드북으로 넘긴다. 다른 후보의 판정은 그대로다
- 가짜 뽑기는 500번이고, 다시 뽑기가 200번으로 줄면 가짜 뽑기도 200번이다. 보고용 틀린 비율 사다리는 끈다

## 가짜 데이터 만드는 법

- 기능 4개 x 안 쓸 이유(nouse) 칸. 앱·웹을 합친다 (11/6 D4)
- 응답자마다 기능별로 `p_nouse` 확률로 "안 써봤다". 안 써본 기능에 이유 1개, 또는 `p_two` 확률로 2개
- 이유는 공통 코드 4개와 기능 코드 4개. 공통 이유 비율은 `common`. 기능마다 가장 많이 나오는 공통 이유가 다르다
- 응답자 70%가 앱, 30%가 웹
- AI는 조건 2, 서비스·플랫폼마다 페르소나 10명. 본실험의 반복 3회는 계산기가 한 사람으로 묶으니 1회로 둔다
- AI 네 가지: 사람과 같은 분포로 답하는 AI, 공통 이유만 말하는 AI, 절반은 사람이 안 말하는 이유를 대는 AI, 순위 뒤집힌 AI(이유 종류는 사람과 같고 많이 말하는 순서만 반대, v1.1)
- 커버리지 실제값: 가짜 데이터라 한 사람이 각 코드를 말할 확률을 안다(`incidence_probs`). 그 칸에서 나온 코드들의 확률 합 / 전체 확률 합이다
- 두 서비스 합친 구성은 사람을 두 서비스에 반씩 나누고, 두 서비스 사람 이유 분포를 같게 둔다. AI는 두 서비스분이다

## 한계

- "사람과 같은 분포로 답하는 AI"는 이상적인 경우다. 실제 AI는 이보다 덜 맞을 것이다
- 쓸 이유(use) 칸과 그만둔 사람(nouse_quit) 칸은 돌리지 않는다
- 정리 담당과 판정자가 코드를 붙일 때 생기는 차이(kappa)는 넣지 않았다
- 이유 코드 구성: 시뮬레이션은 안 쓰는 이유를 공통 4개, 기능마다 기능별 4개로 둔다. 코드북 v0.1(#42, 11/8)은 공통 6개(C01~C06), 기능별 F1 2개·F2 2개·F3 5개·F4 3개이고, 기타(C98)끼리는 맞았다고 세지 않으며 제외(C07)는 판정에서 뺀다. 코드북은 v1.0 고정 전이고 F4 코드는 결정 대기라서, v2는 사전등록대로 지금 구성으로 돌리고 이 차이를 결과에 적는다
- 안정 인원 계산은 끈다 (사전등록 7장에 한계로 적힘)
- 사람 환산 인원도 판정에 안 쓰고 오래 걸려서 끈다. 실제 판정 계산기에서만 낸다
- 두 서비스 사람이 비슷한 이유를 댄다는 가정은 시험하지 않는다 (사전등록 6장)
