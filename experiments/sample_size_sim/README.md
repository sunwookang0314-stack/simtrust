# 사람 수 시뮬레이션 (가짜 데이터)

- 작성: 김민우, 2026-11-06 (11/8 기준 방식으로 고침)
- 질문: 판정 단위 하나(서비스 하나, 또는 합친 두 서비스)에 응답자가 몇 명이면 판정을 믿을 수 있나
- 방법: 먼저 기준을 정하고, 가짜 데이터로 판정 계산기(`scripts/score_reasons.py`)를 그대로 돌려서 그 기준을 넘는 최소 인원을 찾는다 (11/8 강선우 제안). 감으로 정한 인원이 아니라 "이 기준을 넘으려면 몇 명"이 근거가 된다
- 실제 응답은 쓰지 않았고 외부 API도 부르지 않았다. 가짜 데이터로 미리 정하는 것이라 측정 원칙(응답을 보고 기준을 바꾸지 않는다)에 걸리지 않는다

```
python experiments/sample_size_sim/simulate.py --p-nouse 0.25,0.333,0.5 --common 0.3,0.6,0.8
```

7분쯤 걸린다(프로세스 5개). 결과는 `result.json`에 있다. 11/6 첫 실행(기준 없이 판정 비율만 본 것)은 커밋 d99ab1d에 있다.

## 기준 (`criteria.draft.json`, 초안)

| 기준 | 값 | 뜻 |
|---|---|---|
| A | 10% 이하 | 사람과 다르게 답하는 AI(반만 맞는 AI, 공통 이유만 말하는 AI)가 "믿고 써도 됨"을 받는 비율 (강선우 제안) |
| B | 80% 이상 | 사람과 같은 분포로 답하는 AI가 "믿고 써도 됨"을 받는 비율 |
| C | 10% 이하 | 자료 부족 칸 비율 |
| D (선택) | 비워 둠 | 공통 이유만 말하는 AI가 "사람에게 물어볼 것"을 받는 비율 |

- A만 두면 사람이 적을 때 판정이 거의 다 "물어볼 것"이나 "자료 부족"이라 15명으로도 통과한다. 그래서 B를 같이 둔다. 잘못 걸리는 비율과 제대로 잡아내는 비율을 같이 정하는 것이다
- 기준 값은 팀이 정하고, 사람 응답을 보기 전에 `frozen: true`로 바꿔 커밋한다

## 가정

| 항목 | 값 | 출처 |
|---|---|---|
| 판정 칸 | 기능 4개 x 안 쓸 이유(nouse). 앱·웹을 합침 | 11/6 D4 |
| 기능을 안 써본 비율 | 25%, 33%, 50% | 33%는 폼 B 초안의 가정. 파일럿으로 확인할 값 |
| 사람 이유 중 공통 이유 비율 | 30%, 60%, 80% | 가정. 서술이 적으면 이유가 체크 보기(공통 이유)로 쏠려서 80%를 넣었다. 파일럿으로 확인할 값 |
| 한 사람이 대는 이유 | 1개(60%) 또는 2개(40%) | 가정 |
| 앱 응답자 비율 | 70% | 가정 |
| AI | 조건 2, 플랫폼마다 페르소나 10명, 1회씩 | 작업지시서 기준 조건마다 10명 |

AI는 세 가지로 만들었다: 사람과 같은 분포로 답하는 AI, 공통 이유만 말하는 AI, 절반은 사람이 안 말하는 이유를 대는 AI. 인원(15, 20, 30, 45, 60, 90, 120명)과 가정 조합마다 가짜 데이터를 50번 만들었다. 시간 때문에 다시 뽑기는 200번으로 줄였다(본 규칙은 1,000번).

## 결과: 기준 A·B·C를 넘는 최소 인원 (판정 단위 하나당)

"이 인원부터 시험한 더 큰 인원에서도 계속 기준을 넘는" 가장 작은 인원이다. "없음"은 120명까지 못 넘었다는 뜻이다.

| 안 써본 비율 | 공통 이유 | 지금 규칙 (두 기준점 95%) | 두 기준점 90% | 고정 70% | 고정 80% |
|---|---|---|---|---|---|
| 25% | 30% | 120 | 90 | 45 | 90 |
| 25% | 60% | 90 | 90 | 45 | 90 |
| 25% | 80% | 없음 | 없음 | 90 | 없음 |
| 33% | 30% | 90 | 90 | 45 | 120 |
| 33% | 60% | 90 | 60 | 45 | 60 |
| 33% | 80% | 120 | 120 | 45 | 없음 |
| 50% | 30% | 60 | 45 | 30 | 60 |
| 50% | 60% | 45 | 45 | 20 | 45 |
| 50% | 80% | 90 | 90 | 30 | 없음 |

- 고정 60%는 어느 조합에서도 기준 A를 못 넘었다(반만 맞는 AI를 너무 많이 믿는다)
- 기준 D(공통 이유만 말하는 AI를 80% 이상 "물어볼 것"으로)를 넣으면 고정 70%는 전부 "없음"이 된다. 고정 70%는 그런 AI를 대부분 "참고용"으로 두기 때문이다. 나머지 규칙은 숫자가 그대로다
- 경계에 걸친 값은 5%p 안팎 흔들린다(인원마다 칸 200개). 예를 들어 안 써본 비율 33%, 공통 이유 60%에서 지금 규칙은 60명일 때 B가 78%라 아슬아슬하게 못 넘었다

## 읽는 법

- 폼 문서 가정(안 써본 비율 33%)이고 서술이 보통이면(공통 이유 30~60%): 지금 규칙은 90명, 고정 70%는 45명
- 서술이 적어 공통 이유가 80%면: 지금 규칙은 120명. 고정 70%는 45명이지만 30명 이하에서는 사람과 다르게 답하는 AI를 23~41% 믿었다
- 기능을 안 써본 사람이 절반이면 인원이 크게 준다: 지금 규칙 45~90명, 고정 70% 20~30명
- 30명으로 기준을 다 넘는 경우는 안 써본 비율이 절반일 때 고정 70%뿐이다
- 인원은 판정 규칙과 같이 정해야 한다. 고정 70%는 인원이 적게 들지만 "아무 기능에나 할 말"을 거르지 못한다

|---|---|---|
| 두 서비스 합쳐 60명, 합쳐서 판정 | 기준 B가 아슬아슬하게 못 넘음 (78%) | 넘음 |

## 파일럿이 나오면

파일럿에서 기능을 안 써본 비율과 공통 이유 비율을 재서 다시 돌린다. 파일럿이 몇 명뿐이면 대략값이라 그 주변 값을 같이 넣는다. 숫자는 `python scripts/form_to_sheet.py count --detail`로 응답 원문 없이 뽑는다.

```
python experiments/sample_size_sim/simulate.py --p-nouse 0.3,0.4 --common 0.7,0.8 --out experiments/sample_size_sim/result_pilot.json
```

## 한계

- "사람과 같은 분포로 답하는 AI"는 이상적인 경우다. 실제 AI는 이보다 덜 맞을 것이다
- 쓸 이유(use) 칸과 그만둔 사람(nouse_quit) 칸은 돌리지 않았다
- 정리 담당과 판정자가 코드를 붙일 때 생기는 차이(kappa)는 넣지 않았다
- 실제 응답을 모은 뒤에는 계산기의 안정 인원과 포화로 모은 인원이 충분했는지 확인한다
